TFM Quirón · El ciclo del sistema

La rotación del worker

Cómo, al abrir una carpeta y dar permisos, se crea un mundo por proyecto, y a partir de ahí el worker —nuestra red neuronal— trabaja a todas horas convirtiendo lo que hacéis en un índice vectorial verificable. Nada de humos.

Documento visual para la tutoría · complementa el estudio de algoritmos · Qdrant (vectores) + Neo4j (grafo)

🚪 Arranque — abrir un mundo por proyecto

Ocurre una vez por carpeta. Hasta que no das permiso, el editor no lee nada: falla cerrado.

1📁

Abres la carpeta

Como en VS Code. El editor arranca sin proyecto; sin raíz no hay nada que leer.

2🔑

Concedes permisos de agente

Autorizas ese proyecto. Es la puerta: solo ahora el sistema puede mirar dentro.

3🆔

Se crea el ID

Un ULID en <carpeta>/.llore/project.id. Sobrevive a mover y renombrar: es el nombre del mundo.

4📜

Se vuelca el historial

Todos los textos y eventos pasan al líder inmutable (cadena Blake3), etiquetados con ese ID.

AislamientoDesde aquí, cada prompt que envías —y cada acción del modelo— queda marcado con el ID del proyecto. Ninguna unidad de otro proyecto puede aparecer en este mundo.

↻ La rotación — el worker no para

Mientras trabajáis, el worker va detrás, picopala, cerrando este bucle sin descanso.

1

Trabajáis (tú y el modelo)

Cada prompt que envías y cada archivo que se crea o toca es actividad del proyecto.

2

Evento → líder inmutable

Esa actividad se registra como un evento nuevo, con el ID del proyecto. Nadie commitea a mano.

3

El worker lee sin parar

La red lee el registro en continuo y detecta qué ha cambiado (los diffs).

4

Vector + lógica por archivo

Crea/actualiza un vector con el nombre del archivo y le extrae las lógicas de qué hace.

5

Esquema en Qdrant + Neo4j

Escribe el índice filtrado por proyecto: vectores en Qdrant, dependencias en el grafo Neo4j.

↻ …y ese índice fresco alimenta el siguiente prompt → el modelo trabaja mejor y alucina menos → vuelve al paso 1

🛡️ El esquema que sirve de verdad — «nada de humos»

Lo que hace que el índice sea fiable y no un adorno.

✓ Anclado y verificable

Cada unidad lleva ruta, símbolo, rango y hash. Todo lo que se entrega al modelo se puede comprobar contra el código.

✓ Un mundo por proyecto

Qdrant filtra por el ID antes de la similitud; el grafo cuelga de un nodo Project. Cero contaminación entre mundos.

✓ Propone; no ejecuta

El worker no toca el sistema de archivos ni ejecuta nada. Su peor error posible es un grafo que hay que reproyectar — reversible.

✓ Proyecciones desechables

Qdrant y Neo4j se pueden tirar y reconstruir desde el líder inmutable. La verdad nunca se corrompe.

🗂️ Los dos almacenes

SIMILITUD

Qdrant · vectores

Responde «¿qué se parece a esto?». Guarda el vector y el texto semántico de cada unidad, por proyecto.

ESTRUCTURA

Neo4j · grafo

Responde «¿de qué depende esto?» y «¿qué se rompe si lo cambio?». Guarda IMPORTS, CALLS, DEPENDS_ON.

🧠 Cómo es la memoria vectorial — la mente del proyecto

El modelo no recibe la base de datos entera. Con cada prompt viaja un pequeño enlace a dónde está su memoria —la colección de Qdrant y el ID del proyecto—, y el filtro que aísla ese mundo antes de buscar.

Lo que viaja con cada prompt

Un puntero diminuto: dónde están los vectores, dónde el grafo, y el filtro por proyecto.

{
  project : "01J8F…"                  ← el mundo (ULID)
  memoria : qdrant://quiron_events    ← dónde viven los vectores
  grafo   : neo4j://Project/01J8F…   ← y sus relaciones
  filtro  : { project = "01J8F…" }   ← aísla ANTES de la similitud
  k       : 12                        ← cuántos vecinos traer
}

Un punto de la nube

Cada punto guarda de dónde salió, para poder verificarlo contra el código.

{
  id      : quiron/src/api.rs::recall_async
  vector  : [0.021, −0.44, 0.19, …]  (1024 dim)
  payload : ruta   src/api.rs · líneas 88–140
            hash   b3:9f2c…
            lógica "recupera contexto del proyecto
                    y lo rerankea"
}
auth índice api ui datos ◎ tu consulta → vecinos

Los nodos grandes son los módulos del proyecto; los pequeños, cada archivo o lógica (un vector de 1024 dim). Lo que se parece se agrupa por color, pero todo queda entrelazado —también entre módulos distintos—, como en una mente. Las líneas son relaciones del grafo; al consultar ◎ se traen los vecinos más cercanos, y solo de este proyecto.

Comparación del flujo actual —volcar archivos al contexto— frente al worker —recuperación dirigida por grafo + etiquetas verificadas con hash—. La barra es la reducción estimada (base 100 = flujo actual; más barra = más mejora).

Alucinaciones−55 %
Cada fragmento llega con ruta, símbolo, rango y hash verificable; razonas sobre unidades ancladas al código, no sobre memoria difusa del repo.
Lógica duplicada no detectada−70 %
Señal doble —similitud vectorial + vecindad en el grafo— y alerta con dos evidencias; menos re-implementación de lo que ya existe.
Tokens por consulta−60 %
Paquete de contexto acotado y relevante en vez de volcar archivos enteros; el ahorro crece con el tamaño del proyecto.

Estimación ilustrativa para la defensa, no resultado medido —el índice aún no existe—. Se refinará con un corpus etiquetado. El efecto es mayor cuanto más grande el proyecto: en un repo pequeño apenas se nota; en uno de decenas de miles de unidades es donde el worker paga.
Abres la carpeta → das permisos → nace el ID → el historial va al líder inmutable → y el worker gira sin parar convirtiendo cada archivo en vector + lógica sobre Qdrant y Neo4j. Cuanto más grande el proyecto, más te ayuda.
